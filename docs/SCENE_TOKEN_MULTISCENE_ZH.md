日期：2026-09-08。状态：书架新视角、数据隔离、八卡主训练、完整恢复与采样验收均已完成；局部新视角有支持，多场景高质量重建尚未通过。

## 本轮问题

用户选择std0.02作为后续工作点，并授权验证同场景新视角、8场景学习及未训练场景V2/V6。当前保留S256、distinct 1D位置编码、已有DA3冻结；不同时引入解冻、正交初始化或scene-only注意力。

## 2. 深度监督的预留帧隔离

原pilot的伪深度由DA3-Giant以最多16张图的round-robin组联合生成。因此“未把预留RGB直接送给学生网络”不必然排除它通过其他帧深度监督间接提供信息。

逐帧核验发现，上述书架的6个微调RGB帧所对应的teacher输入共94帧，与选出的11张新目标帧交集为空。因此书架结果通过这项补充审计。

但8场景全轨迹训练会遇到这一风险。已停止最初刚启动的主训练（8个rank均82步，656次场景曝光），保留为`multiscene_20260908_v1/train_v1`并标记不可作为最终结果；没有沿它继续训练。为正式实验新建：

`/data/datasets/3dvision/ZipSplat-scene-token/heldout_isolated_20260908_v1/`

对全部10个场景，在teacher输入中排除各场景8个固定评估目标，只重算受影响分组中非预留帧的深度，共1160张。未受影响的深度保留，预留帧自身的旧深度只用于评估损失，不进入训练输入或监督。每张非预留深度的teacher输入帧清单已保存并检查交集为空。

3326帧的RGB字节、相机和位姿与原数据一致；全部深度可解码、有限且有效率大于98%。teacher权重与原始图/变换文件哈希核验通过，原pilot未覆盖。

## 3. 多场景训练与评估协议

使用已有8个训练场景和2个验证场景，先冻结预留集合，再生成隔离后的标签。每场景选择轨迹中部的18帧跨度窗口，若原pose-jump guard不通过则确定性平移窗口；不根据图像质量挑选。

相对窗口起点a：V2输入为[0,18]；V6输入为[0,3,7,11,15,18]；8个目标为[2,4,6,8,10,12,14,16]。V2是V6子集、目标和跨度相同。8训练场景共64个预留目标，从所有训练context和target中排除。在线使用原bounded采样并拒绝包含预留帧或触发原pose-jump guard的组合；训练context顺序仍随机。先检查512个样本，随后每一步记录并强制检查排除条件。

这是条件于“不含预留帧”的采样分布，可能降低预留窗口附近的采样频率，不能称完全等同未设预留的原采样器。每场景只固定一个局部评估窗口，不是全轨迹/官方benchmark。

模型从released权重重新开始，随机初始化scene参数std0.02；不从已拟合书架的checkpoint起步。保留原AdamW、betas0.9/0.95、weight decay0.05、clip1、BF16、新参数LR3e-4、既有下游3e-5、10步warmup。八卡同步平均梯度，每卡固定负责一个场景，每步动态采样2context+4target，global batch为8场景。

完成5000次全局优化器更新，合计40000次场景曝光，每场景5000次。**这不等同于B1顺序训练40000次优化器更新**；批量和梯度平均方式已改变，学习率未按batch线性放大，不能把结果当成只改变场景数的严格单因素对照。CPU缓存解码视图，仍复用官方相机/深度归一化，不是正式DataLoader吞吐测试。

每场景5000次曝光也不等于每张图被监督5000次：每次从约300张允许帧中采样4张目标，监督量分散到整条轨迹。最终逐帧曝光次数保存于validation.json；不能直接用动态采样5000步的模糊程度与固定4张书架图5000步比较，进而判定表征容量不足。

评估集合分开保存：

- `train_probe`：8个固定允许训练的采样组合，每场景一个，均在第1步真实训练过；不等于全部动态训练数据的平均效果。
- `trained_scene_v2`：8个已训练场景的严格预留目标，V2。
- `new_scene_v2`：2个未训练场景，V2，与训练视角数一致。
- `new_scene_v6`：同2个未训练场景和目标，V6；用于视角数迁移。总高斯数从16384增至49152，不是同预算纯输入信息量对照。

0/500/1000/2500/5000步保存固定指标和所有图像，不用这些目标做模型更新、配准或TTO。新验证窗口与旧跨度149帧的V6验证不同，不能直接横向比较旧验证分数。

## 4. 多卡工程验收

正式训练前完成8卡实际模型20步冒烟（160次场景曝光）。四类关键参数的DDP梯度与手动all-reduce后平均比较，最大相对误差约2.05e-11；跨rank可训练参数哈希一致、完整model/optimizer/scheduler/scaler恢复通过。这个检查使用原pilot标签，是工程验收，不作质量结论。

隔离后主训练复用同一实现，并在新数据上再次执行0更新的梯度平均检查后才开始优化。每步检查关键梯度和指标有限、优化器步数连续；阶段性检查各rank参数一致。源码和初始参数哈希、每rank采样/LR/梯度/耗时均留档。

训练采样的连续500步均值（分别截至1000/2000/3000/4000/5000）PSNR为13.849/14.345/14.678/14.925/15.109，LPIPS为.6586/.6421/.6282/.6192/.6161。仍在改善但速度减慢，不能认定已经充分收敛。

查看四组所有场景的固定首张目标对照：从近乎黑图逐渐出现室内墙面、椅子/屋顶/草地的大致颜色分布和粗轮廓，但大多数细节没有形成，书架仍无可辨认的书脊，存在大量线状伪影。新道路场景接近灰褐色平面，雕像场景可见天空/植被的大致分区但雕像未可靠重建。即使个别简单场景PSNR较高，也不能当成几何或细节重建通过；全部目标图均在页面中保留，不只展示首张。

2500→5000：已训练场景预留视角PSNR提高.237dB，未训练V2下降.612dB而LPIPS改善.0098，说明优化收益不均匀，不能说所有指标都退化，也不能说新场景稳定受益。最终V6平均PSNR比V2低.366dB、LPIPS高.0020，未见总体收益；两个场景中的PSNR变化方向也不一致，不能据此认定多视角输入通常无效。

本轮结论是：固定书架模型有局部新视角能力；共享模型能够学习多场景粗信息，但当前训练和新场景均未达到高质量重建。不能把问题全部归为跨场景过拟合，因为已训练场景自身仍明显欠拟合；也不能据一次有限预算实验判定S256容量不足、std0.02不合适或必须解冻DA3。

### 采样与恢复验收

- 8个rank各5000步连续更新、关键梯度有限非零、LR轨迹一致、所有采样避开64个预留目标；冻结参数哈希不变，可训练参数最终跨rank逐字节一致。
- 每场景3712–4018个不同有序context组合，296/338/300/379/338/298/307/320张允许帧全部被采到，共2576张；每张图作为target的中位次数按场景为73/63/72/55/62/72/69/67次。范围最少1次、最多103次，不是每张图5000次。逐帧计数保存在validation.json。
- 从最终checkpoint新建单卡模型，严格恢复model/optimizer/scheduler/scaler及更新计数通过；所有优化器状态步数5000，样本计数40000。checkpoint保存八rank RNG状态，但没有额外进行分布式恢复后更新轨迹等价实验。
- 四个集合的每个场景total loss/PSNR/LPIPS重放误差均0；1280张阶段性GT/渲染PNG全部存在。已核验训练源码、数据tar与teacher输入排除清单。

### 实际资源

八张H100同步训练主运行墙钟约34.38分钟（包括加载、评估、保存），约4.58 GPU小时；每rank训练步中位.351–.356秒，峰值分配显存约9.73–9.75GiB（训练开始后重置统计，包含后续评估）。这是冻结DA3、V2、252分辨率、CPU缓存视图的实验口径，不能外推全量数据加载或DA3联合微调。

本地页面：[书架监督/新视角对照](F:/Development/multiview/ZipSplat/results/scene_token/bookcase_novel_20260908_v2/comparison.html)、[多场景逐步对照](F:/Development/multiview/ZipSplat/results/scene_token/multiscene_20260908_v2/train_v1/comparison.html)。多场景页面包含全部128个目标项的五阶段GT/渲染图，可切换集合、场景和目标帧；指标为所选场景全部target均值。

即使多场景拟合改善，也需要分别看未训练场景及新视角，而不是仅看训练loss。颜色KV仍读取原图，尚未进行scene信息贡献消融、同预算原版竞争力验证、联合DA3微调或更多S预算实验。两验证场景只能用于小规模开发，不能代表全数据泛化。

下一步建议先做8场景固定context/target的受控拟合对照，保留std0.02/S256/同一八场景平均梯度及学习率，将数据变化与共享模型适配困难拆开：若固定多场景能拟合而动态采样不行，再研究训练量和采样；若固定多场景也困难，再比较有限DA3适配与冻结方案。它仍不能单独给出容量/优化瓶颈的因果结论。之后按主计划补scene贡献与同预算原版对照，不直接扩大到全量训练；这些后续实验本轮尚未执行。
