## 2. 研究目标与不能混淆的结论

目标：在 DA3 编码中加入每视角 S 个可学习场景槽位，只把指定层的场景特征送入几何解码，研究质量、表示冗余与预算的关系。

- 第一版全程保留原 patch，只在输出时提取场景槽位。这是学习式几何输出瓶颈，不减少 DA3 编码 FLOPs；序列变长可能增加耗时与训练显存。
- 原 ZipSplat k-means 减少 query 和高斯数，几何 CA 仍读取全部 patch 特征。它的压缩率曲线不是新场景表示的容量极限，也不是严格上下界。
- 第一版保留独立原图颜色 KV。因此不能声称只存场景 token 就能离线独立解码整个场景。
- 固定每视角 S 时总量为 VS，仍随视角数增长，不等于固定全场景预算或自动消除跨视角冗余。
- GVC1D 提供学习式 latent 读取思路；视频条件编码、空间分块 global 模块不直接移植为 DA3 跨视角注意力。

## 3. 记号与公平预算

默认图像 252×252、patch14，P=324；DA3-Giant D=1536。V 为视角数，S 为每视角场景槽位数，K 为解码 query 数，G 为高斯总数。

原模型保留比例 r（不是移除比例）：

`K = min(VP, max(1, floor(rVP)))`，`G = 32K`。

新模型首版关闭第二次 k-means：`K=VS`，`G=32VS`。之后若研究二次选择，则使用单独参数 `scene_query_ratio`，不得与原始 patch 保留比例混淆。

同预算对照须匹配实际 K 和 G。原模型 r≈S/P，但必须验证整数取整；必要时在实验层提供明确的 query 数覆盖项，保证选择算法和其余前向不变。不能只比较相同数值的 r。

## 4. P0：固定评测和可复现基线

### 4.1 输入与数据划分

- 主线使用 NoPrior：重建只接收 context RGB，不传 GT 内外参；GT 仅按明确协议用于监督或配准/渲染。
- 优先复用 short60 已有10场景的 context 清单；初始完整矩阵使用共同有效9场景，排除既有缺GT的06。不得重新随机抽样冒充同一输入。
- 初始 V 为4/8/12/16。对每个场景固定8个 held-out target，优先从前60帧中、所有 context 集合的并集之外均匀选取。必须先核验帧图像、GT和预处理；不足8个时在运行前确定替代集合并版本化，不能运行后补选。
- 输入重建指标与 held-out 指标分开。target 不进入重建的图像、特征或缓存。
- 后续训练集来自 DL3DV-10K 有效清单；核验与全部验证/测试场景无重复，按场景划分并冻结清单。交接中10485完整/96异常属于历史检查结果，运行前重新核验。
- 9场景用于预实验和开发选参，不据此宣称最终泛化；正式结果需保留未参与选参的场景集合。

### 4.2 相机、图像和指标

- 保存原图到模型/渲染图的裁剪缩放、内参转换、OpenGL/OpenCV约定、首视角归一化和尺度配准。
- 初始新实验采用252×252评测图像，PSNR/SSIM/LPIPS-Alex v0.1；核对实现、输入范围与聚合方式后写入配置。同一次比较不得混用256尺寸旧报告或VGG版本LPIPS。
- 相机配准方案A：由 r=1 基线在 context 上确定一次配准与相机，跨比例复用，作为固定相机敏感性对照。若压缩引起输出坐标系漂移，该对照会同时包含漂移影响，必须披露。
- 方案B：各比例使用相同初值、步数和损失的独立配准，作为固定预算配准后的质量对照。优先使用 context 做共享坐标对齐，再渲染 held-out；若必须用 target RGB 优化其位姿，单列“target RGB pose-refined”结果，不能标成未经适配的NVS。
- P0须核验A/B可执行性并固定主报告协议；方案A与B的结果不得混成一条曲线。现有30步context配准不自动等于held-out评测流程。
- 汇报逐场景均值与跨场景等权均值，失败/跳过显式列出；不让帧数不同的场景隐式改变权重。

### 4.3 环境和复现

记录源码HEAD及未提交差异、checkpoint路径/SHA256、配置、数据manifest、软件/CUDA/GPU、dtype、随机种子和实际导入路径。原模型保持eval、固定checkpoint，不训练、不做高斯TTO。

## 5. P1：原始 ZipSplat k-means 压缩率预实验

### 5.1 问题和矩阵

只改变k-means保留比例，测原模型在不同query/高斯预算下的质量退化与耗时，不改变backbone、颜色路径、每token高斯数或权重。

| 步骤 | 初始设置 | 目的 |
|---|---|---|
| 冒烟 | 1场景、8视角、r=1与1/8 | 验证索引、计数、输出和指标 |
| 小规模粗扫 | 3场景×8/16视角×6比例，共36组 | 覆盖低纹理、细节丰富、遮挡/大视差；运行前写明场景ID与选择依据 |
| 完整粗扫 | 9场景×4/8/12/16视角×6比例，共216组 | 复用已完成且配置完全一致的子集，不重复计数 |
| 拐点细扫 | 在相邻粗扫点之间插值 | 同一规则选择区间；完整披露，不仅保留最佳点 |
| 固定K对照 | 选所有V都可支持的公共K，跨V比较 | 分开观察观测量与高斯预算影响 |

六个保留比例：`1, 1/2, 1/4, 1/8, 1/16, 1/32`。若到1/32仍未显著退化，可扩展更低预算，但将其标为训练分布外压力测试，不能保证单调性。

优先依据r=1的相对变化报告曲线；初始质量预算采用PSNR下降≤0.5/1.0/2.0dB三个档位，分别给出该档的最小实测K，同时列出SSIM与LPIPS变化及视觉缺陷。这些是报告分档，不是声称统一可接受阈值；后续工作点在看训练/验证结果后明确记录，最终测试不参与选择。

### 5.2 计时、缓存和稳定性

- 分开记录预处理、backbone、k-means、几何/颜色解码、高斯head、配准、渲染，以及端到端wall time和峰值显存。
- GPU计时同步边界，固定warmup和重复次数；初始为3次warmup、10次计时取中位数，记录离散程度和设备占用。质量输出不必重复导出十次。
- 可以缓存原backbone特征加速质量扫参，但缓存键必须含模型/图像/预处理/dtype/层号；缓存运行耗时不能当成完整推理耗时。端到端性能另行跑完整前向。
- 查明k-means初始化是否随机；若随机，对代表场景与拐点用3个种子复测。记录实际K、必要时记录唯一nearest索引数，以识别重复选择。
- 缺文件/GT或运行失败时记录具体原因，不能静默忽略或覆盖已有结果。

### 5.3 产物和验收

拟用独立结果根 `/root/multiview_compare/experiments/scene_token/kmeans_sweep/<run_id>/`，报告根 `/root/multiview_compare/reports/scene_token/<run_id>/`；部署时检查目录再登记，当前尚未创建。

每次保存配置与版本、输入manifest、逐组K/G/指标/耗时、渲染对照和失败表。报告至少包含逐场景曲线、均值曲线、固定K跨V对照、细节裁剪与最小预算分档。CSV/JSON保存明细，Markdown解释结论；PLY/视频按代表点保存，不能覆盖旧short60。

P1验收：所有计划组均有结果或明确失败记录；实际预算和指标口径核对通过；能给出后续S的候选区间。结论写成“原解码器预算曲线”，不得写成“场景只能/至少由S个token表示”。若发生非单调结果先检查选择稳定性、相机漂移和失败点，不强行平滑成单调曲线。

## 6. P2：场景 token 首版结构

### 6.1 Backbone 与多层接口

- 从完整ZipSplat checkpoint初始化，保留其DA3适配权重；不只用原版DA3覆盖主干。
- 新增共享初始化参数 `[S,1536]`，展开为 `[B,V,S,1536]`，前向状态独立。槽位随机初始化以打破对称性，不创建按训练图/视角ID记忆的参数。
- 原patch全程保留，注意力层数、宽度、头数和原局部/全局调度保持；所有槽位参与相应注意力。首版不加入ToMe、熵编码或自适应预算。
- 原patch先完成绝对位置插值，再插入场景槽位；不能把S计入二维网格。首版场景RoPE采用特殊token零位置，以不同学习槽位向量区分身份；此为设计假设，记录并验证。
- 保留camera索引0与block13注入；明确camera/register/scene/patch的切片和位置数组。global普通patch的RoPE在当前实现中不是唯一视角ID。
- 输出19/29/39对应local18/global19、local28/global29、local38/global39；每组场景特征 `[B,V,S,3072]`，沿用归一化/prepare成为 `[B,V,S,1536]`。
- 三层保持相同槽位顺序。反转后的融合次序仍为39→29→19。K=VS，几何CA的KV仅含场景槽位，不得不经说明继续读取稠密几何patch。

### 6.2 颜色分支与高斯head

原颜色特征来自独立可学习 `Conv2d(3,128,kernel=14,stride=14)`，每图324个patch；不是DA3降维或RGB均值。

```text
几何CA/SA融合后的 scene [B,K,1536]
      ├──────────────────────────────┐
      ↓ 新 Linear(1536,128)          │
颜色 query [B,K,128]                 │
      ↓ 原完整 Color CA block        │
      ↑ 原图颜色 KV [B,VP,128]       │
颜色输出 [B,K,128] ───── concat ─────┘
                  [B,K,1664]
                       ↓ Gaussian head
                  G=32K 个高斯
```

- 新增query投影，保留128维color CA、1664维head输入与每token32个高斯，尽量复用权重。
- 严禁把场景nearest_idx直接gather原图颜色patch：即使不越界，也会取错视角/位置。
- Color CA保留原归一化、残差、MLP语义。新增投影与颜色CA需要适配；原颜色KV缺少显式位置/视角编码，重复纹理、曝光/反光混合是待验证风险。
- 首版不取消颜色skip，避免同时改变head输入形状。颜色必须进入压缩瓶颈、位置/视角编码和显式匹配留作后续消融。

- 禁用新功能时与基线数值等价；新增token初始化为零不构成等价保证。

## 7. P3：分阶段训练与 S 选择

初始候选S为32/64/128，P1结果可调整候选范围并记录原因。首个完整实验从S=64开始；每个S使用对应训练配置和相近更新预算，不把直接截断已训练槽位当成公平S对照。

1. 小数据过拟合检查：验证端到端损失确实下降，排除坐标、渲染、梯度和颜色路径错误；该结果不能作为泛化证据。
2. 热身：冻结DA3已有参数，训练新场景token、颜色投影以及下游prepare、几何CA/SA、颜色CA、高斯head。冻结DA3仍需为场景token保留梯度路径。
3. 联合适配：逐步解冻DA3后部，再根据验证集决定是否全量微调。分组学习率，新参数通常高于预训练参数；具体值、batch、步数在P3启动配置中确定并记录，不臆定硬件可承受规模。
4. 按固定验证协议比较S，不用最终测试集选参。永久冻结decoder仅作为消融，不作为主方案成立前提。

沿用并审计现有训练入口的渲染/几何监督、尺度正则和相机口径；重建输入不得含target特征。训练监督可使用target RGB，但测试时它不能进入重建。初版不引入GAN来掩盖几何误差。

观察：输入/held-out指标、槽位特征相似度与有效秩、梯度、opacity分布、高斯覆盖、细小结构和重复区域。槽位相似本身不等于无效，结合重建与预算消融判断。特征蒸馏不能把VS与VP按索引逐点MSE；若引入蒸馏，优先固定相机下渲染目标或明确的匹配/聚合机制。

P3验收：有可复现实验配置、训练曲线与未参与训练场景的结果；至少一个S稳定训练且无显著接口故障。若失败，先定位颜色/槽位塌缩/监督问题，不能只加大S或把冻结decoder的失败直接解释为研究方向无效。

## 8. P4：同预算评估与决策

核心对照：原ZipSplat同K/G、新模型对应S；另列原r=1参考。视角/图像/相机/指标保持P0协议一致。记录整网耗时，即使新模型更慢也如实报告。

优先消融：S预算、DA3解冻范围、decoder联合微调vs冻结；颜色失败明显时再增加位置/匹配变体。每次只改变一个关键因素，避免训练预算不同造成错误归因。

P4产物：同高斯预算的质量/速度曲线、逐场景退化、可视化、槽位分析、最终checkpoint/config与限制说明。若只有输入视角改善，不能称为NVS提升；若只有高斯更少，不能称为DA3加速。

## 9. P5：首版验证后的独立研究

- 中途丢弃patch，让后续编码真正变短；额外检查早期场景容量与local/global输出接口。
- 全局仅场景token交互、局部保留patch；需要设计跨视角信息回传。
- 二次k-means、可变S训练、按场景复杂度自适应预算，区分槽位身份与内容相似性。
- 将颜色也压入瓶颈，实现不依赖原图颜色KV的表示；单独报告信息预算和效果。

这些不并入首版实现，也不提前声称有加速或质量收益。
