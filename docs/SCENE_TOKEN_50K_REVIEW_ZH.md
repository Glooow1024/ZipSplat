## 已确认的事实

- 运行正常完成 50,000 步，metrics.jsonl 恰有 50,000 条；status=complete，无 error_rank 文件。最终 checkpoint 为 checkpoints/step_050000.pt（9,639,104,919 字节）。本次没有重新加载该 checkpoint 做恢复等价测试。
- 实际 255 个训练场景、32 个验证场景；global batch=8 场景，4 target/场景。累计 400,000 次场景曝光，平均约 1,569 次/训练场景，但每次视角组合变化，不能理解为每帧监督 1,569 次。

## 原因判断：事实与假设分开

1. **学习率尾部过小解释了后期变化慢的一部分。** 不能由尾部曲线证明容量饱和，也不能保证重启学习率就恢复细节。原运行已经完成，不能直接以现有零 LR 追加步数；续训需新阶段及明确的调度/优化器恢复策略。
2. **适配范围较保守。** 读取 layers 19/29/39，却只解冻 30–39。前两路输出仍会随 scene 参数训练改变，梯度可穿过冻结块，但前两路之前的旧注意力权重无法适应新压缩任务。这是候选限制，不是已确认根因，也不据此直接解冻全模型。
3. **压缩约束强于原 k-means 对照。** 原版压缩 query 后仍从全量 dense patch KV 聚合；当前几何聚合只能看到 scene-token KV。S256 的数量与 75% 保留预算接近，信息保真度没有等价保证。颜色分支仍访问全部颜色 patch，但 query 已从选中 patch 改为 geometry 投影，局部颜色对应是否准确尚未诊断。
4. **几何和纹理问题尚未拆开。** 高斯位置/尺度、相机配准、伪深度误差、颜色读取或表示细节不足都可能表现为模糊。现有日志未单独测量其贡献，不把模糊直接归为 token 坍缩、渲染随机不稳定、GS 数量不足或分辨率上限。当前已有 LPIPS 0.05，不是漏加感知损失。

## 与论文训练长度的关系

[ZipSplat 论文 §4.1、Appendix A/B](https://arxiv.org/html/2606.05102v1)报告 450k、16 GH200、RE10K/DL3DV 等比例混合、2→24 context、联合微调、252px。当前是 released ZipSplat 全权重上适配新 scene-token 路径，并非从论文 DA3-only 初始化重新训练整套网络；数据、batch、视角数、可训练层和学习率均不同。450k 是论文训练预算，不是本项目必须达到的收敛阈值。论文评测还优化 target 相机对齐，当前不做，绝对 PSNR 不能直接横比。

## 建议的后续优先级（尚未执行）

- 支持继续训练，但不机械在旧 50k 调度尾部加步数，也不承诺训练到 450k 会自然变清晰。保留 std0.02/S256，建立合理非零 LR 的新阶段；记录固定验证、训练拟合、高清纹理区域及各 loss，不只监控 total。
- 为泛化扩到 1024–2048 个训练场景，再逐步扩大；9820 是候选而非全部清洗通过。沿用隔离验证/官方测试，并增加相机轨迹与伪深度异常审计。扩数据不自动修复训练集也模糊的问题，不应仅反复循环这 255 个场景。
- 若合理 LR 下训练和验证仍共同模糊，优先定位多层特征适配与几何/颜色对应；考虑更早层的有限解冻或低秩适配，需要后续实现和验证。
- 不将全部跨视角 attention 立即改成 scene-only。它可减少全局计算、强迫信息经过 scene tokens，但同时去掉 dense patch 跨视角对应通道，增大瓶颈和预训练分布变化，不是保证提高清晰度的修复。后续结构研究优先保留早期全量交互，仅在少数后期全局层尝试；相机 token、位置编码及局部 patch↔scene 交互须一起设计。该实验不与当前续训混称单变量效果。
