# ZipSplat k-means 预实验结果

日期：2026-09-07。实验：`20260907_v2`。342组质量实验及32个独立性能配置全部完成，完整覆盖核验通过。

## 覆盖与口径

- 9个有效short60场景，4/8/12/16输入视角，每场景固定8个与所有context不重叠的held-out target；06缺GT排除。
- 216组粗扫 + 108组拐点细扫 + 18组固定K补点 = 342组。固定K=324/648的其余视角点复用相同K的粗扫，最终两种K均覆盖9场景×4视角数。
- 原始ZipSplat权重与模型源码不变；未加入场景token、未训练。主体FP32/关闭TF32，k-means内部精度策略沿用原实现。
- 主表B：每个预算只用context RGB拟合相同预算的共享Sim(3)，随后将同一变换用于target。target RGB不参与模型或配准。A复用r=1配准作为诊断，独立保存。
- 252×252、白背景、PSNR/SSIM/LPIPS-Alex v0.1；针孔近似，无逐target位姿优化。不能与旧256×256/逐视角优化报告直接比较。

模型前向是预处理后GPU输入→高斯，3次warmup后10次计时中位数再跨组平均，不含CPU预处理、磁盘、配准、渲染和指标。包含预处理的性能另列完整报告，不能混用。

在本次总体均值与已测比例里，将PSNR损失控制在0.5/1/2dB内的最低保留率分别为75%/50%/25%。这是经验工作点，不是所有场景都满足的承诺；逐场景最小预算在quality_budgets.csv中。

高斯减少8倍时模型前向只加速约1.13倍；降至约1/32高斯预算时，模型前向约1.15倍，但PSNR已经损失9.33dB。新增压缩发生在主干之后，DA3计算基本不受影响。

独立性能测试（04/05两场景）也支持这一点：16视角时，100%与3.125%保留率的backbone均约359ms；包含CPU裁剪缩放/H2D的RGB→高斯耗时为1866.9ms与1795.9ms，仅约1.04倍。两者峰值显存约6.17GiB与6.04GiB。CPU预处理开销与主机负载有关，不能外推到已预处理GPU输入或优化后的数据管线。

## 图像观察与实现检查

- 04/05/09对照图中，强压缩使墙上文字、商品包装、栏杆和植被细节退化；3.125%出现明显模糊/拉伸。逐场景曲线差异明显，保留原始非单调点，不强行平滑。
- k-means唯一索引占K的均值在压缩点均超过99.9%，低预算退化不能解释成大批重复选点。算法仍未被修改为强制唯一选择。
- v1冒烟及v2 pilot中，拆分缓存前向与直接前向、重复直接前向的高斯参数最大绝对差为0。v2包含12个此类预算配置检查。
- 342组预算/帧集/相机复用/有限指标和抽样PNG指标复核通过；PNG量化后重算PSNR最大偏差约0.00686dB。`verify_kmeans.py --complete`同时确认216粗扫、108细扫、18补点和32性能配置齐全。

## 对场景token研究的影响

- 本实验的几何CA仍读取全部VP个几何特征，颜色CA也读取完整图像特征，因此这里测的是原解码器query/高斯预算曲线，不是VS个编码特征的容量极限。
- S=32/64/128对应S/P约9.88%/19.75%/39.51%的原模型匹配query预算；32是较激进的压缩，64和128也不是无需训练的无损替换。
- 2026-09-07用户明确接受的视觉参考是保留75%，不是移除75%。据此更新计划：最初参考S=243，用户随后指定S=256且P2已实现，对应约79.01%保留率，同K/G基线须补测；后续按验证结果尝试162/81，对应r=0.5/0.25。旧32/64/128作为可选扩展或接口冒烟配置，不再把64视为保守主预算。每个S须训练验证，不能承诺与同K的k-means相同质量。
- 首版DA3保留patch并新增scene槽位，S=256将每视角patch+scene长度变为580，需在完整训练前验证显存和前后向成本。这里的输出压缩不等于编码加速；k-means的全局选点也不等同于每视角固定分配S。
- P2已完成，见SCENE_TOKEN_IMPLEMENTATION_ZH.md；下一阶段是P3数据/训练配置准备、小样本验证与联合适配。尚未正式训练。
