# Scene token 初始化尺度：重复性定位与三种子长拟合

日期：2026-09-08。状态：已完成 6 组训练，每组 1000 次更新，共 6000 次；全部恢复与诊断检查通过。已有 DA3 冻结，尚未完成联合微调或 P3 高质量重建验收。

## 1. 结论与推荐

标准差 0.08 相比 0.02，在三个配对种子上都提高了固定书架的 PSNR、降低了 LPIPS。书架横板、部分书脊与颜色区域已经可以辨认，不能把“仍未达到高质量重建”描述成“完全没有学到信息”。但验证场景平均 PSNR 更低、LPIPS 更高，不能把固定样本拟合收益推广为整体性能收益。

建议保留 **0.08 为后续拟合实验的候选工作点、0.02 为必要对照**。本轮未修改正式默认初始化。当前主要限制已经包括固定单场景过拟合、已有 DA3 冻结和下游对新表征的适配，不能继续仅凭第一层 cosine 或有效秩选择最优尺度。

## 2. 为什么相同配置也会得到不同结果

此前 position-distinct 与 scale1 的初始参数哈希、共同源码哈希、配置、第一步 loss 相同，但第一次反向的 scene 参数梯度已略有不同，随后训练轨迹分叉。本轮通过同一计算图重复反向定位，不更新参数，也不把随机初始化差异混入诊断。

诊断分为完整 loss、仅渲染输出平方均值、仅 scene features 平方均值。每组重复三次 `autograd.grad(..., retain_graph=True)`，下表给出后两次相对第一次的梯度相对 L2 差异范围：

| 模式与目标 | scene features 梯度差异 | scene 参数梯度差异 |
|---|---:|---:|
| 原运行设置，完整 loss | 7.75e-6–1.08e-5 | 0.537%–0.663% |
| 原运行设置，仅特征 | 不适用 | 0.274%–0.507% |
| 受控设置，完整 loss | 4.03e-6–4.62e-6 | 0.529%–0.584% |
| 受控设置，仅渲染 | 3.72e-6–1.03e-5 | 0.436%–0.636% |
| 受控设置，仅特征 | 不适用 | **逐位相同** |

完整 loss 对 rendered RGB 的梯度在两种模式下均逐位相同。受控设置消除了本次观测到的纯特征路径反向差异，但渲染相关路径仍引入微小扰动，回传到 scene 参数时相对差异增大。安装中的 gsplat `rasterize_to_pixels_bwd.cu` 第 255–273 行使用 `gpuAtomicAdd` 累积梯度，是符合该现象的机制证据；尚未逐个 CUDA kernel 证明唯一根因。不能据此声称排除了所有其他非确定性来源。

受控设置：cuDNN benchmark=False、deterministic=True、`torch.use_deterministic_algorithms(True)`、`CUBLAS_WORKSPACE_CONFIG=:4096:8`。PyTorch 的确定性标志不能完整约束自定义 gsplat CUDA 算子。只读 `GaussianHead.metrics` 的 median-with-indices 会被严格模式拒绝，工具仅在这一 `no_grad` 健康统计中临时关闭标志并在 finally 恢复；loss 与反向保留严格设置。正式模型和渲染器源码均未修改。

诊断 v1 曾错误地对新生成的 Gaussian 属性 view 请求梯度，被 unused 检查拒绝；另一失败来自上述只读 median。v2 修正，v3 增加仅渲染分支。失败日志保留，所有诊断均为 **0 次优化器更新**。权威诊断目录为 `vllm1:/root/multiview_compare/experiments/scene_token/repeatability_20260908_v3/`，其中保留实际安装包路径、CUDA 源码和哈希。

## 3. 配对训练协议

- 三个初始化种子 256/257/258，每个种子从同一份 Gaussian 参数分别取 std0.02、乘 4 得 std0.08；仅初始化时缩放，恢复或每次前向不再乘系数。每个种子两组缩放前参数哈希相同，三个种子的初始化哈希互异。
- 全部使用同一组数据，数据加载种子固定 256；种子 257/258 在缓存数据后重设初始化随机状态。因此比较的是初始化敏感性，不是不同采样数据的效果。
- S256、distinct 1D scene Q/K RoPE、全部 40 个 block、base10000、位置 scale1；不锚定二维网格、不加时间编号。patch 与 scene 仍共同参加既有注意力。
- 所有 1000 步固定拟合书架 `7e6564c7...`，B1、V2、4 个 target、252px，context186/194，target187/189/190/193（零基）。不是遍历全部训练集。
- 两个固定验证场景，每场景 V6、8 个互斥 target；NoPrior，GT 相对相机和 context-depth 尺度用于监督/渲染，无相机配准或 TTO。不是论文官方 benchmark。
- 已有 DA3 冻结，训练 scene slots、新颜色 query 和既有下游。新参数 LR3e-4、下游3e-5，AdamW betas0.9/0.95、weight decay0.05、clip1、10 步 LinearLR warmup、BF16；完整损失与此前一致。两组绝对 LR 相同，因此尺度与相对参数更新幅度的影响不能完全分离。
- 本轮所有训练启用上述受控运行设置；与此前 benchmark=True 的 200 步运行不构成只有训练步数变化的严格对照。趋势应优先看本轮自己的 step200/500/1000。
- 三个种子分别用 GPU0/1/2 独立运行，不是 DDP。预定 step0/200/500/1000 保存全部训练与验证渲染/指标，step1000 保存 checkpoint；没有按最好指标筛选种子或终点。

下表为三个种子的均值 ± 样本标准差（ddof=1）。验证值先在固定验证场景内按工具协议汇总，再对种子统计。三种子、两个验证场景不足以证明统计显著性或最优超参数。

| 0.08 | 16.799 ± 0.998 | 0.4805 ± 0.0762 | 8.477 ± 1.036 | 0.8483 ± 0.0763 |

## 5. 可视化与表征诊断

结果目录 `../results/scene_token/scale_repeats_20260908_v1/` 中：

- `bookcase_comparison.png`：三个种子逐行、GT/0.02/0.08 逐列，固定相同 target。
- `bookcase_progression.png`：预先固定 seed256，0/200/500/1000 步；没有挑最好种子。
- `validation0_comparison.png`、`validation1_comparison.png`：两个验证场景，相同排版。
- `training_curves.png`：每个种子的训练 loss、训练 PSNR、验证 PSNR。
- 各 arm 的 step 目录保留全部 target 原图/渲染，不能把拼图中单一 target 当成全部验证结果。

已人工检查：书架出现多层横板和书脊/封面颜色区域，seed257 的整体覆盖更完整；0.08 常有更明显的局部细节，但并非所有区域覆盖都优于 0.02。图像仍模糊，有弯曲线条、空缺和伪影。验证图像没有同步恢复可靠几何，出现块状、尖刺和类似书架横纵纹理的伪影，符合固定场景过拟合的风险。不能仅凭这些图证明模型完全忽略输入。

step1000 的每视角去均值熵有效秩：

| 种子 | 标准差 | DA3 末层 | 几何融合后 | 颜色输出 |
|---|---:|---:|---:|---:|
| 256 | 0.02 / 0.08 | 20.81 / 26.20 | 4.79 / 9.93 | 2.70 / 7.02 |
| 257 | 0.02 / 0.08 | 22.07 / 25.41 | 11.44 / 16.29 | 4.78 / 6.80 |
| 258 | 0.02 / 0.08 | 21.80 / 23.95 | 6.20 / 8.83 | 4.06 / 5.71 |

0.08 的分化在这些位置更强，但有效秩不等于信息量、可重建质量或需要的 token 数；一维身份编码和随机噪声也能抬高秩。S256 是否足够仍未由本轮证明。

## 6. 工程验收、成本与恢复

`validation.json` 已通过：6000 步连续更新、关键梯度有限且非零、两组 LR 轨迹一致、六组冻结 backbone 哈希相同、配对初始化与固定数据一致。18 组逐层 trace 的 hooks 前后，scene/全部五类高斯参数/渲染最大绝对差均为 0。

六个 checkpoint 均在新建模型上严格加载，恢复后 loss/PSNR 差均为 0；重复前向的上述输出也逐位一致。未配置位置 adapter 的加载被拒绝。本轮未追加 optimizer 续训一致性检查，也不声称跨进程训练逐位一致。

恢复时先按 `conf.experiment` 安装 `ScenePosition1D`，再 strict 加载；保留持久化 `backbone.backbone.scene_position_experiment_spec`，不能 strict=False 忽略。std 缩放已写入参数，不要再次乘 factor。

H100 单步更新中位约 0.297–0.309 秒；峰值 allocated 约 8.96–14.48GiB，包含验证/逐层诊断和同进程运行历史，不能据此断言 0.08 本身需要更大训练显存。缓存 B1/V2、冻结 DA3 的时间不能外推全模型微调、多视角 DataLoader 或 DDP。六个 checkpoint 合计 44,231,153,110 字节（44.23GB），仅保留服务器，不下载本地。训练与恢复检查均已结束，GPU 无本任务残留进程。
